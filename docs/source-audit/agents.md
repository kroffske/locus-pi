# Source audit: agents

Decision: command-side single-agent `/agent run` plus tool-safe `spawn_agent`/`task`, both on the local `createAgentSdkSessionExecutor` / public `createAgentSession` SDK path. This slice keeps `agents` as a local `.agents/agents/*.md` catalog and routes both triggers through the same `executeAgentRunBoundary`; `/agent run` additionally owns the shared live row/panel. One tool call accepts one `task` string and creates one child. Parallel jobs belong to workflow orchestration.

T-113 update: the programmatic `task` tool introduced real headless child spawning from tool `execute()` via host SDK `createAgentSession` (`extensions/_shared/agent-sdk-host.ts`, `createAgentSdkSessionExecutor`). `ctx.newSession` is structurally unreachable from a tool ctx, so the importable SDK was the correct substrate. The current `/agent run` path now uses that same SDK executor and `executeAgentRunBoundary`, plus command-side live rows; an older host without `createAgentSession` degrades to an honest fail-closed for either trigger.

T-101 update: child sessions receive `agent.systemPrompt` as an active persona through `DefaultResourceLoader.appendSystemPromptOverride`. A successful child returns its exact final non-empty text; JSON-looking text is not parsed, markers and result envelopes are unsupported, empty output fails, and unavailable host remains `blocked`.

T-101 read-only enforcement update: `readOnly: true` now narrows the SDK child
to `read`, `grep`, `find`, `ls`, `yield`, and explicitly requested `git_read`.
Shell, write/edit, nested workflow, and unknown custom tools are absent from the
session even when requested. `git_read` invokes `git` directly without a shell
and accepts only allowlisted local query subcommands; mutation, output-file,
external diff, textconv, pager, signature, and runtime config options are
rejected before process launch. Write-capable agents keep their declared tool
surface. The regression test inspects the real SDK session options, runs a safe
status query, and proves a checkout mutation is blocked.

T-123 update, rechecked against the declared `@earendil-works/pi-coding-agent@0.82.0` peer: `CreateAgentSessionOptions` supports child cwd, model, thinking level, tool allow/deny lists, custom tools, resource loader, session/settings managers, and session start metadata, but no first-class `response_format`, `json_schema`, or `outputSchema` option. Pi's documented structured-output example is a terminating tool-result pattern (`terminate: true`), and `--mode json` is an event-stream mode. Local default output remains text; explicit structured mode is a future Locus-owned design, not JSON-by-default.

T-138 update: `task.agent` is optional and resolves through the shared agent resolver. Missing `agent`, `agent: "default"` and `agent: "general"` select the bundled `task` agent; `general` stops being an alias when a real project/user `.agents/agents/general.md` exists. Unknown-agent errors now use one human message for `task`, `/agent run`, and `/agent inspect`: `Unknown agent: "<name>".`, available agents, built-in aliases, and `/agent list` hint. The same error writes a diagnostic artifact under `.locus/runtime/artifacts/*.json`. `task` returns unknown-agent and child-session failures as `ToolResult` errors with text `content`, structured `details`, and `isError=true`.

T-111 selection update: the resolver above is unchanged, but the caller no longer has to guess the name it feeds into it. `refreshAgents` formats the resolved first-match-wins definitions into bounded `name — description` lines and writes them onto the `agent` property of the shared `TaskParams` schema used by `spawn_agent` and `task`; a `before_agent_start` hook refreshes them once per turn. The parameter schema was chosen over the tool description and over a system-prompt block because the declared `@earendil-works/pi-coding-agent@0.82.0` peer copies `ToolDefinition.description` by value when it wraps a tool but passes `parameters` through to the provider by reference on each request, so only the schema field is both adjacent to the choice and refreshable without re-registering the tool. The advertisement is bounded — at most 12 entries, each description clamped to 96 characters (the same cap `extensions/workflows/workflow-catalog.ts` applies to workflow descriptions), with the remainder stated as `+N more — /agent list` — because a narrow default surface is a project non-goal boundary, not an oversight. It is advertisement only: an unknown or invented name is still refused by the unchanged unknown-agent path with its available-agent list, built-in aliases and diagnostic artifact.

T-138 child-policy note: the SDK child-session path passes `cwd`, allowed tools, model and optional `appendSystemPrompt` to `createAgentSession`. No confirmed Pi SDK option is used here to inherit parent yolo/approval policy into nested child sessions, so the local docs describe that policy as not inherited rather than claiming hidden propagation.

T-209 viewer update supersedes the T-116 product viewer while keeping `/agent drill` as compatibility entry. `/ps` and `/agent ps` use the same resolver and open a local `AgentSessionViewer`: shared inline editor-replacement surface, native assistant/tool components, terminal-height fill, follow-tail/detail controls and return without abort. When no child transcript exists, the generic viewer renders status-aware recorded row text plus optional source/error evidence; it does not label every writer's terminal payload as a final answer. Workflow replay verification remains the workflow adapter's responsibility before projection into that row. The implementation is local/write-from-scratch; `ctx.switchSession()` is not used because installed Pi replaces the parent runtime rather than attaching the live child.

Historical T-192 fleet-input note (superseded by T-209/W8): Pi's installed loader proves that each extension entrypoint gets a fresh `jiti` with `moduleCache:false`; the former module-local `agentLiveStore` therefore split `agents` from `workflows`. A versioned `globalThis[Symbol.for(...)]` store now provides the narrow process-local seam, with reset on `session_start`. The former focus surface experimented with platform-specific `super+down`/`ctrl+down` and terminal-compatible `shift+down`; owner Terminal evidence showed that the modifier pair was unreliable on macOS (`alt+a` inserted a character). A live installed-Pi tmux run proved `shift+down → focus → arrows → Enter → drill` while `/workflows run` was still executing; a separate raw Kitty modifier probe reached the same focus component. Both are synthetic terminal transport evidence, not physical-key acceptance. A slash-command fallback was rejected because synchronous command execution cannot process it until the workflow finishes. That historical editor-replacement component captured keys without rendering rows; the current focused component renders the same row grammar as the passive fleet, subscribes to live-store mutations, and disposes that subscription when focus closes. RPC receives updating `string[]` rows instead of an ignored factory. Resolver exact/normalized/ambiguity behavior is explicit; drill `uuid` means only `childSessionId`; overlay listeners dispose on close/completion/reload. `Enter` drills the exact selected row, `x` aborts that row's actual SDK child controller, and `Esc` returns. The behavior is local/write-from-scratch; official Pi extension, TUI, RPC-mode, and keybinding docs supplied the `setWidget(..., { placement:"belowEditor" })`, `ctx.ui.custom()`, `registerShortcut`, injected keybindings, and `keyHint()` contracts.

T-206 static-presentation update: `/agent list`, `/agent inspect`, unknown/incomplete command and target paths, and headless settled-result chrome now project existing catalog/run facts into the local shared typed operator block. Full catalog/inspect use the shared inline TUI scroll surface; RPC/passive fallback is deliberately compact and keeps source counts, overflow and recovery visible. The fleet, focus menu, drill, cancellation, resolver and live store are unchanged domain surfaces. This presentation code is local/write-from-scratch and does not copy OMP catalog semantics.

T-226 semantic work is retained but reconciled by T-209 into one typed owner instead of a second string timeline. Stable blocks correlate tools by `toolCallId`, preserve bounded assistant snapshots/structured results, redact sensitive keys and cap per-message items plus aggregate bytes/nodes. `latestMessage` is a projection of the same timeline. Raw `eventLines` remains bounded diagnostic data. Terminal result honesty is unchanged: non-empty answer required; provider and child-result errors remain separate.

2026-07-10 child-boundary/interrupt update: child `turn_end.message.usage` now feeds live per-row input/output tokens, while terminal `getSessionStats().tokens` remains the cumulative authority. Workflow group rows derive a descendant token sum for the visible summary. Every SDK child receives `excludeTools: ["spawn_agent", "task"]`, which current Pi applies after `tools`; wildcard write-capable profiles therefore cannot directly nest agents, while `workflow` remains allowed when selected by that profile. Read-only profiles use the stricter T-101 capability boundary above. Bundled profiles no longer advertise `spawns`; external legacy metadata is displayed as blocked. Bare `Escape` that would reach `app.interrupt` during an active parent turn with live agent rows now requires `ctx.ui.confirm`; fleet/drill `Escape` only closes the view and reports that work continues, and focused `x` asks before selected-child cancellation. This implementation is local/write-from-scratch and follows current official Pi SDK (`excludeTools`), extension (`ctx.abort`, `ctx.ui.confirm`, terminal input) and keybinding (`app.interrupt=escape`) contracts.

Historical 2026-07-11 fleet-input update (superseded by T-209/W8): physical macOS behavior made modifier chords an unreliable primary surface: `Ctrl+Down` is owned by macOS window management, and `Alt/Option+A` inserts a character. An intermediate implementation used the official `ctx.ui.getEditorText()` plus `ctx.ui.onTerminalInput()` seam to consume bare `Down` only in TUI when editor text was exactly empty and fleet rows existed; `Up` stayed native. `Shift+Down` remained the registered fallback. This intermediate bare-arrow path is no longer active; the current contract is recorded below.

2026-07-13 T-209/W8 fleet-input reconciliation: `extensions/agents/index.ts` leaves bare `Up`/`Down` to Pi, preserving native cursor/history behavior in every editor state. Fleet entry is explicit through `/ps` or registered `shift+down`; once focused, arrows move the ephemeral selection. `extensions/_shared/fleet-menu.ts` keeps aggregate/group rows visible for context but excludes them from cursor selection, `Enter`, `x`, and `last`; direct aggregate ids return guidance naming child rows. The implementation is local/write-from-scratch, and focused regression tests in `tests/extensions/agents/agent-fleet-menu.test.ts` and `tests/shared/agents/agent-fleet-rows.test.ts` cover the leaf-only selection and explicit shortcut contract.

Source reference note for T-116: checkout-relative `pi-subagents:src/ui/conversation-viewer.ts` and `pi-subagents:src/ui/viewer-keys.ts` were used as reference material for the overlay/viewer and keyboard-scrolling pattern. The local implementation was adapted to the Locus live-store shape and Pi custom UI contract; it was not copied from pi-subagents and is not a full pi-subagents conversation viewer parity port.

T-167/T-168/T-169 update: live rows now keep richer source-backed optional fields and render them through the shared local `AgentLivePanel` in `extensions/_shared/agent-live-panel.ts`. The fields include model/thinking, activity state, current path, bounded tool args, turn count, token count, child session id, result artifact, final answer, and group counters when current runtime events or local workflow journal lines provide them. Unsupported upstream states such as detached, paused, needs-attention, async control, or fabricated token/tool data are not emitted. `/agent drill` reuses the same row facts plus the bounded transcript projection for child-session viewing and still does not claim exact full conversation-viewer parity.

Historical M11 note: `extensions/_shared/agent-executor-host.ts` retains the former replacement-session contract and tests as provenance/reference, but the active `/agent run` entrypoint no longer calls it. Current command execution is `runAgentLiveTask` -> `createAgentSdkSessionExecutor` -> `executeAgentRunBoundary`; no parent session replacement or replacement `sendUserMessage` occurs.

T-120 update: `buildAgentSystemPrompt` now supports optional context extras via injected env configuration when `LOCUS_AGENT_CONTEXT_EXTRAS=1`. Memory extras load from `LOCUS_AGENT_MEMORY_FILE` or `<projectRoot>/MEMORY.md` with line+byte caps and missing-file diagnostics; skill extras load only from explicit `LOCUS_AGENT_PRELOAD_SKILLS` entries and resolve simple names through `.agents/skills/<name>/SKILL.md` then `.pi/skills/<name>/SKILL.md`. Missing/invalid entries are reported as non-fatal diagnostics. No default preload list is configured, and this behavior is opt-in.

Source note for T-120: the prompt shape is adapted from checkout-relative `pi-subagents:src/prompts.ts` (parent/shared prompt first, then stable sub-agent bridge, then active-agent tag, then env/persona, then optional extras suffix), but no external runtime implementation was copied. The local implementation in `extensions/_shared/agent-context-extras.ts` owns the bounded file readers, deterministic ordering, and diagnostics; it intentionally does not claim full pi-subagents parity and still keeps extras disabled unless the operator explicitly turns them on.

Current local state:

- `extensions/agents/index.ts` is the entrypoint; it calls `task-tool.ts` to register primary `task`, `workload-proof-tool.ts` to register the proof-evidence tool `locus_workload_proof`, and `command-router.ts` to register `/agent` and `/ps` through the shared command UI lifecycle helper that clears transient `agents` widgets/status on the next unrelated user input or slash command.
- `/agent list` can show markdown definitions from project `.agents/agents`, user `~/.agents/agents`, and bundled `.agents/agents`.
- Agent catalog records preserve local metadata: `tools`, `spawns`, `model`, `thinking-level`, `blocking`, and opaque nested `output`.
- `task.md` and `quick_task.md` carry ordinary frontmatter in the same `.agents` catalog as the other definitions.
- `/agent run` uses the SDK child-session executor, updates the process-shared live row/panel, and reports `completed`, `failed`, `cancelled`, or `blocked` through live or typed settled chrome.
- `/agent list`, `/agent inspect`, `/agent observe`, and `/agent summary` render transient `agents` widgets; `/agent observe` and `/agent summary` render an on-demand bounded snapshot of live rows from `agentLiveStore.rows`; done/error rows remain terminal, not running, and the observer never claims full pi-subagents parity.
- `/agent drill <row-id|agent|last>` opens the shared inline custom UI over the Locus live store, with scroll and close keys, when the Pi host exposes custom UI; otherwise it reports an honest unavailable message in the `agents` widget.
- Fleet input uses `/ps` or registered `shift+down`; bare `up`/`down` stay with Pi. Aggregate/group rows remain visible headings, while only leaf rows are actionable and aggregate targets receive child-selection guidance.
- `/agent run` writes a best-effort `.locus/runtime/artifacts/*.json` result artifact with launch metadata, model role metadata when available, exact text, diagnostics, lifecycle entry ids, and child output stats. Unknown-agent errors also write a diagnostic artifact, but that artifact is not execution proof.
- `locus_workload_proof` writes diagnostic persisted evidence under `.locus/runtime/agent-workload-proof/*.json` for reviewer and agent flows that have performed bounded child workload. This persisted evidence does not control parser success by itself.
- `spawn_agent`/`task` spawns one real headless child session for one required `task` string and returns exact child text to the caller; it returns `isError=true` when the host cannot provide `createAgentSession`, when a child run fails/blocks/cancels, when text is empty, or when agent resolution fails.
- `extensions/_shared/agent-executor-host.ts` retains the former replacement-session adapter and its parser/host tests, but it is not the current `/agent run` executor. Active slash/tool execution owns parsing, artifacts, diagnostics, cancellation and stats through `_shared/agent-sdk-host.ts` plus the shared run boundary.
- `extensions/_shared/agent-context-extras.ts` owns opt-in memory and skill suffix resolution, bounded line/byte clamps, default `MEMORY.md` lookup, and non-fatal diagnostics when requested assets are missing.
- `extensions/agents/session-viewer.ts` owns the native full-viewport viewer and one Pi-version capability seam. It renders a bounded readable `finalAnswer`/artifact fallback when no transcript exists, preserving replay evidence honesty. `extensions/agents/drill-overlay.ts` now retains only the reusable static text overlay and historical-round type; the obsolete second live-view owner was deleted.
- `extensions/_shared/agent-live-panel.ts` owns the shared local row formatter, including status text, bounded row detail fields, group summaries, and parent/child row ordering via `AgentLiveRow.parentRowId`.
- `extensions/workflows/progress-widget.ts` owns only workflow-specific compact progress layout and delegates row text rendering to `AgentLivePanel`; the focused agents component derives and caps current global rows itself.
- `tests/extensions/agents/agent-observer.test.ts` covers empty state, running-row summary, terminal done/error rows, and bounded duplicate/noise collapse.
- A 2026-06-03 real Pi repair smoke proved one manually loaded parser-clean command-only `/agent run quick_task ...` path after source repair. Its raw transcript had zero assistant tool calls, so it did not prove child workload execution, tool-safe execution, completed-run artifacts, broad UX, or default package promotion.
- A 2026-06-08 promotion smoke proves the default-loaded command surface and records child workload counters for `/agent run`.
- A 2026-06-13 real-Pi live proof promoted `task` into a working executable tool path: a programmatic call spawned a genuine child that made a real `read` tool call and returned a real tool result. The current text-only contract supersedes that proof's former model-written JSON envelope while retaining the child-spawn and workload evidence.
- The SDK host now collects exact tool names from its real `tool_execution_*`
  subscription before live-UI projection and passes the normalized set through
  `AgentChildOutputStats.recordedToolNames` to the pure evidence evaluator.
  Aggregate SDK counters are not converted into names; exported JSONL remains
  audit evidence, not a runtime fallback parser.
- A 2026-06-03 OMP comparison proves that real OMP `TaskTool` child workload evidence includes assistant `toolCall` entries and matching `toolResult` entries. That comparison is evidence for the expected proof shape, not an implementation of OMP `TaskTool` inside `locus-pi`.
- The extension is loaded by default through `package.json#pi.extensions`.

Implementation boundary:

- Do not keep the old deterministic summary as execution proof.
- `task` is product-ready: retained SDK-host tests and release-candidate Pi smoke cover tool-context child spawn through `createAgentSession`, genuine child workload, abort/timeout handling, JSONL evidence export, and exact final-text return. Keep the honest fail-closed for hosts that do not expose `createAgentSession`.
- `/agent run` and `task` both use `createAgentSession`; `ctx.newSession` is not part of either active execution path.
- Keep discovery scoped to `.agents/agents` so agent files have one local convention.
- Keep `/agent drill` scoped to bounded Locus row/transcript observability. Do not claim exact pi-subagents conversation-viewer parity; any broader port requires a separate parity review.
