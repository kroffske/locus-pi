# Code of Conduct

## Our standard

Project participation must be respectful, specific, and safe. Contributors and
maintainers are expected to:

- discuss ideas and defects without personal attacks or harassment;
- critique behavior, evidence, and trade-offs rather than people;
- respect privacy, confidentiality, and coordinated vulnerability disclosure;
- avoid discriminatory, sexualized, threatening, or deliberately disruptive
  conduct;
- accept maintainer decisions about scope, safety, and release gates while
  remaining free to document a reasoned disagreement.

This standard applies to repository issues, pull requests, discussions, review
artifacts, and other project-controlled spaces. It also applies when someone is
publicly representing the project.

## Enforcement

Report ordinary conduct concerns through the repository's private maintainer
contact features when they are available. Do not include security vulnerability
details; use the process in `SECURITY.md` for those reports.

Maintainers may edit or remove harmful content, pause a discussion, reject a
contribution, or temporarily or permanently restrict participation. They should
apply actions proportionately, preserve relevant evidence privately, avoid
retaliation, and explain the project impact when doing so is safe.

Before the repository is opened publicly, the owner must verify that a private
conduct-reporting route exists. Lack of such a route is a community-readiness
gap, not permission to publish personal contact information.
